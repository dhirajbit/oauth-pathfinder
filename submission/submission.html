The problem I solved

A developer whose agent needs users to connect Gmail, Slack or Salesforce must register an OAuth app with that provider — and sometimes get it approved. The question nobody answers up front is “is this a 10-minute form or a 6-week review?” Google wants a paid CASA assessment for Gmail scopes; Dropbox freezes new links at 50 users; Salesforce stopped creating Connected Apps in Spring ’26; Slack takes ten minutes. The facts exist but are scattered, and never framed as time, effort and blockers.

What I built

  • Library of 123 OAuth apps with a triage difficulty, the one thing that decides it, and whether Composio offers a managed OAuth app (from the managed-auth directory).
  • 10 full guides across different setup challenges, researched by agents reading provider docs, then spot-checked by a person.
  • Live generation for any app: one investigator agent (OpenAI Responses API + web search) reads the docs and writes a guide validated against the same schema.
  • Shareable without accounts: library guides have permanent URLs; generated guides are encoded into the link itself. Copy as markdown, download JSON.

Every guide answers the same questions:

  • Verdict strip — difficulty, hands-on minutes, approval wait in days, time to first token on one proportional bar
  • Ordered steps, each tagged Agent / Agent + you / You, with portal links
  • Scopes that trigger review; approval triggers, review time, what reviewers ask for, common rejections
  • Nuances, blockers with workarounds, and the agent/human handoff plan
  • Evidence: sources with confidence, what was confirmed on the page, what is still unverified

Evidence & verification

Spot-check of 12 consequential claims (Google, Slack, Salesforce, Dropbox) against the cited pages: 11 confirmed, 1 corrected (Google max wait 60 → 63 days: the sum of its own cited figures), 0 unverifiable. Pattern: numbers quoted from official pages were right; derived figures and review turnarounds are where errors live, and docs are silent on exactly the things only registering an app would settle (token lifetimes, key propagation delay). Details in VERIFICATION.md.

Key decisions & limitations

  • Time and effort are the headline, not the steps — that is what decides whether to use a managed app, pick another provider, or start the review now.
  • One schema for library and live output, so the library grows by generating and reviewing rather than writing from scratch.
  • No database: share links carry the guide; credential-free and permanent, at the cost of long URLs.
  • Not attempted: logging into developer portals to register apps with the agent (needs real accounts and 2FA). Live guides are not person-reviewed and inherit search quality; review turnaround numbers are often community-sourced.

Stack: Next.js 16, TypeScript, Zod, OpenAI Responses API with hosted web search, Vercel. ~7 hours. No credentials in the repository.
